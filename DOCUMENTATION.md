## 1. Обзор и ключевые особенности

Плагин совмещает в себе передовую сессионную архитектуру **JamDungeons** (GUI-админка, волновые PvE/PvP бои, схематики WorldEdit, MariaDB хранилище, ваучеры наград) и проверенные временем алгоритмы авто-спавна из **RDang**:

* **Оптимизированный спавн без лагов:** тяжелые проверки мира разнесены, 3D-сканирование коробки данжа использует дискретный шаг (`check-step: 3`), снижая нагрузку на CPU более чем на 95%.
* **Асинхронный CoreProtect:** координаты точек собираются в основном потоке, а проверка истории блоков игрока выполняется асинхронно через CompletableFuture.
* **Мульти-измерения:** правильный подбор высоты в Незере (под бедроковым потолком, а не на крыше), Энде (на островах), обычном мире, а также поддержка летающих, надводных и подводных данжей.
* **Автоматические приваты WorldGuard:** накладываются при создании данжа со строгими защитными флагами и бесследно удаляются при победе, поражении, отмене или откате ландшафта.
* **Откат территории:** исходный рельеф мгновенно и безопасно восстанавливается через WorldEdit/FAWE без повреждения окружающих построек.

## 3. Полный список команд

Команды можно выполнять через любой алиас: `/jd`, `/jamdungeons`, `/dungeons`, `/rdang`, `/rd`, `/dang`.

### Основные и меню
* `/jd help` — вывод интерактивной справки по командам.
* `/jd menu` — открыть главное меню администратора (GUI):
  * Список и статус арен;
  * Редактирование точек и сундуков;
  * Настройка тем, шансов и пулов наград;
  * Ручной запуск и откат.
* `/jd edit <id>` — открыть GUI редактирования конкретной арены с идентификатором `<id>`.
* `/jd status` — подробная системная сводка в чат:
  * Статус интеграций (WorldGuard, WorldEdit, CoreProtect, Vault, PhoenixCrates);
  * Список активных сессий (фаза, волна, владелец, оставшееся время);
  * Статус планировщика авто-спавна.
* `/jd validate` — полная валидация целостности всех арен (проверка точек выхода, точек мобов, сундука, коллизий приватов).
* `/jd reload` — горячая перезагрузка всех YAML-конфигураций (`config.yml`, `themes.yml`, `rewards.yml`, `messages.yml`) и обновление определений регионов.

### Управление спавном и событиями
* `/jd spawn <id> [site]` — заспавнить данж в мире:
  * Если тип размещения случайный (`GROUND`, `AIR`, `WATER`, `UNDERWATER`), плагин автоматически найдет идеальное свободное место с учетом биома, рельефа и CoreProtect.
  * Если тип `STATIC` или указан `[site]`, данж появится на фиксированной подготовленной площадке.
* `/jd test <id> [site]` — запустить данж в **тестовом режиме**:
  * Волны мобов и механика боя работают полноценно;
  * Не списываются жизни игрока;
  * Отключена выдача ценных реальных наград.
* `/jd stop <id>` — принудительно остановить событие:
  * Игроки безопасно выводятся на точку выхода;
  * Все мобы данжа деспавнятся;
  * Приват WorldGuard удаляется;
  * Ландшафт восстанавливается к состоянию до спавна данжа.
* `/jd wave <id> <1-5>` — принудительно запустить определенную волну мобов (для тестов баланса).
* `/jd timer <pve|pvp> <секунды>` — изменить длительность сессии на лету.

### Работа со схематиками и шаблонами
* `/jd template save <id>` — сохранить выделенную область арены в шаблон (`templates/<id>.schem`). Все точки мобов и сундук автоматически привязываются относительно постройки.
* `/jd schematic list` — список доступных файлов схематик в папке плагина.
* `/jd schematic use <id> <файл.schem>` — привязать файл схематики к арене и автоматически рассчитать габариты A/B и безопасный выход.
* `/jd schematic paste <id>` — вставить постройку арены в мир по точке A.

### Настройка точек и сундуков
* `/jd chest <id>` — установить сундук арены на блок, на который смотрит игрок.
* `/jd point add <id> <exit|1..5> [mob] [radius]` — добавить точку выхода или точку спавна моба для волны.
* `/jd point remove <id> <номер_точки>` — удалить точку.
* `/jd point clear <id> [exit|1..5]` — очистить все точки или точки конкретной волны.
* `/jd point list <id>` — список всех настроенных точек арены.
* `/jd point view <id>` — визуализация точек цветными партиклами в мире.
* `/jd site add <id> <name>` — добавить фиксированную площадку для статического спавна.
* `/jd site remove <id> <name>` — удалить площадку.

### Интеграции, конфиги и аудит
* `/jd case list` — список доступных ключей из PhoenixCrates.
* `/jd case map <donation|epic|resource> <case_id>` — связать категорию наград с ID кейса.
* `/jd config set <config|themes|rewards|messages> <путь.в.yaml> <значение>` — быстрое изменение параметров прямо из чата/консоли.
* `/jd audit [строк]` — просмотр последних записей журнала административных действий из MariaDB.
* `/jd review` — просмотр очереди недоставленных наград (при выходе игрока или сбоях сети).
* `/jd review <id> <owner> <delivered|retry>` — подтвердить доставку или повторить отправку награды.

## 4. Механика спавна и подбора локаций

При автоматическом или случайном спавне алгоритм проходит многоступенчатую проверку:

```
[Поиск мира] ➔ [Случайный радиус (min..max)] ➔ [WorldBorder & Spawn Distance]
     ➔ [Проверка биома (арена/тема)] ➔ [Дистанция до игроков]
          ➔ [Асинхронная предзагрузка чанков]
               ➔ [Расчет высоты (Overworld/Nether/End/Water/Air)]
                    ➔ [Ступенчатая проверка естественности рельефа]
                         ➔ [Дистанция до других активных данжей]
                              ➔ [Коллизии с чужими регионами WG]
                                   ➔ [Асинхронная проверка CoreProtect]
                                        ➔ [СПАВН + СОЗДАНИЕ WG ПРИВАТА]
```

### Высота по измерениям:
1. **Обычный мир (`NORMAL`):** используется карта высот `MOTION_BLOCKING_NO_LEAVES` с контролем уклона (`max-ground-slope`) и плотности твердого грунта (`min-ground-coverage: 0.80`).
2. **Ад (`NETHER`):** сканирование ведется **сверху вниз от Y=115 до Y=32** (под коренной породой потолка), пока не будет найден устойчивый блок ландшафта с воздухом над ним. Данж никогда не появится на бедроковом потолке.
3. **Край (`THE_END`):** поиск поверхности островов Энда (блоки `END_STONE` и `OBSIDIAN`) на высотах от 80 до 40, исключая пустоту.
4. **Воздушные данжи (`AIR`):** размещаются на высоте от `air-min-height` до `air-max-height` блоков над землей в свободном воздушном пространстве.
5. **Водные и подводные данжи (`WATER` / `UNDERWATER`):** проверяется поверхность океана, глубина водоема и погружение корпуса (`water-submerge-blocks`).

## 5. Интеграция с CoreProtect

Для предотвращения порчи построек игроков внедрен двухфазный алгоритм:
1. **Сбор контрольных точек (Главный поток):**  
   По сетке с шагом `coreprotect.sample-step: 4` сканируются блоки поверхности и ключевые внутренние точки габарита данжа (до `max-samples: 64`).
2. **Анализ истории (Асинхронный поток):**  
   Плагин запрашивает историю каждого блока через `CoreProtectAPI.blockLookup(...)`. Если в логах есть действие игрока (`actionId == 1`) без системного префикса (игнорируются природные теги `#water`, `#fire`, `#environment`), локация бракуется с причиной `постройки игроков (CoreProtect)`, и плагин моментально переходит к следующей попытке без лагов сервера.

## 6. Регионы WorldGuard и жизненный цикл

На каждый заспавненный данж накладывается защитный кубоид с настраиваемыми отступами (`protection.horizontal-padding: 3`, `vertical-padding: 8`).

### Накладываемые флаги:
* **Запрещено (`DENY`):**
  * `BUILD`, `BLOCK_BREAK`, `BLOCK_PLACE` — полная защита от строительства и ломания блоков;
  * `TNT`, `CREEPER_EXPLOSION`, `OTHER_EXPLOSION` — защита от всех видов взрывов;
  * `FIRE_SPREAD`, `LAVA_FIRE`, `LIGHTER` — защита от огня, лавы и зажигалок;
  * `DAMAGE_ANIMALS`, `GHAST_FIREBALL`, `RESPAWN_ANCHORS` — защита от урона животным и фаерболов;
  * `PVP` (в PvE-режиме) — защита игроков от урона других игроков.
* **Разрешено (`ALLOW`):**
  * `CHEST_ACCESS` — открытие сундука с наградой;
  * `USE`, `INTERACT`, `ENTRY` — взаимодействие с механизмами/дверями и вход в данж;
  * `MOB_SPAWNING` — спавн мобов волн данжа;
  * `PVP` (в PvP-режиме) — свободные сражения за сундук.

### Удаление региона:
Регион удаляется автоматически и гарантированно через `WorldGuardRegions.delete(...)` при:
* Успешной зачистке и сборе наград;
* Истечении таймера данжа;
* Ручной остановке администратором (`/jd stop <id>`);
* Перезапуске или перезагрузке сервера.

## 7. Система волн мобов и темы

### Прогрессия волн:
Каждый PvE-данж состоит из **5 последовательных волн**:
1. Волна 1 спавнится в момент активации данжа игроком.
2. Новая волна начинается, когда **убиты все мобы текущей волны** (`combatants.isEmpty()`), либо когда истек таймер волны (`wave-interval-seconds`, по умолчанию 180 сек).
3. При победе над 5-й волной данж завершается, и открывается доступ к наградам.

### Темы по умолчанию (`themes.yml`):
* **`mining` (Шахтёрский):** Зомби в броне, пауки, чешуйницы, скелеты, ядовитые пещерные пауки.
* **`forest` (Лесной):** Утопленники, пауки, скелеты, болотники (`BOGGED`), ведьмы.
* **`flying` (Летающий):** Скелеты, фантомы, ветреники (`BREEZE`), шалкеры.
* **`desert` (Пустынный):** Кадавры (`HUSK`), кадавры с копьями, пустынники, пауки.
* **`water` (Водный):** Утопленники ближнего боя, утопленники с трезубцами, разбойники.
* **`raiders` (Разбойники):** Разбойники, поборники (`VINDICATOR`), ведьмы, заклинатели (`EVOKER`), досаждатели (`VEX`), разорители (`RAVAGER`).

## 9. Пошаговое создание нового данжа

1. **Постройте данж** в строительном мире или скопируйте схематику в папку `templates/`.
2. **Создайте арену:**
   * Откройте меню администратора: `/jd menu`.
   * Нажмите **«Создать арену»**, укажите ID (например, `crypt_1`) и выберите режим (`PvE` или `PvP`).
3. **Привяжите постройку:**
   * Встаньте в угол постройки и выполните:  
     `/jd schematic use crypt_1 crypt.schem`  
     *(Плагин установит размеры постройки и рассчитает точку выхода).*
4. **Установите сундук:**
   * Подойдите к главному сундуку с наградой, посмотрите на него и введите:  
     `/jd chest crypt_1`
5. **Настройте точки спавна мобов:**
   * Встаньте в точку, где должны появляться мобы, и добавьте ее для волны:  
     `/jd point add crypt_1 1 zombie 2`  
     *(Точка для волны 1, моб zombie, радиус разброса 2 блока).*
   * Повторите для остальных волн (2, 3, 4, 5).
6. **Сохраните шаблон:**
   * Выполните: `/jd template save crypt_1`.  
   * Все координаты зафиксируются относительно точки центра.
7. **Проверьте данж в тестовом режиме:**
   * Выполните: `/jd test crypt_1`.  
   * Пройдите волны мобов, проверьте баланс урона и корректность спавна.
8. **Остановите тест:**
   * Выполните: `/jd stop crypt_1`. Ландшафт автоматически откатится.
9. **Готово к авто-спавну!** Теперь арена будет автоматически спавниться по расписанию или через команду `/jd spawn crypt_1`.
